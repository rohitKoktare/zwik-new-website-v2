# ZWIK Website

Premium D2C storefront and admin panel for ZWIK miniature decor.
Next.js 16 (App Router) + Supabase (Auth / Postgres / Storage), deployed on Vercel.

Orders are **not** taken on the site. The cart is a message builder: it composes
a WhatsApp message and hands the customer off. No payment, no accounts, no
customer PII stored. See `docs/ARCHITECTURE.md` §1 and §5.

## Setup

The Supabase backend is already provisioned and verified. You need
`Website4/.env.local` with the four keys listed in `.env.example`.

```bash
npm install
npm run verify:setup   # confirms schema, RLS, Storage, admin user, WhatsApp config
npm run dev
```

Storefront: <http://localhost:3000> · Admin: <http://localhost:3000/admin/login>

For a brand-new Supabase project instead, follow `supabase/README.md`.


## Rules that are easy to break

- **Never** import `SUPABASE_SERVICE_ROLE_KEY` (or `lib/supabase/admin.ts`)
  into a client component.
- Admin writes go through `lib/admin/*/actions.ts`: authorize, validate, write,
  audit, then revalidate via `lib/admin/revalidate.ts`. Skipping the audit or
  the revalidate is a bug, not an optimisation.
- The WhatsApp number and default message come from `site_settings`, never a
  constant. When WhatsApp is unconfigured, hide the affordance — never render a
  dead link.
- URL-encode the WhatsApp message exactly once, at link-build time.
- Media URLs are built only by `lib/storage/resolve-asset-url.ts`.
- Don't disable caching to make an admin edit show up — fix the revalidation.
